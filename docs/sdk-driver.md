# SDK driver — Fase 1, increment 1 (thin, safe, flag-off slice)

Implements step 1 of `docs/sdk-migration-plan.md` §4: a **per-card SDK driver** that can run a card's
Claude session through the Agent SDK (`query()`) instead of the tmux/send-keys TUI. It is **opt-in,
OFF by default, and purely ADDITIVE** — with the flag off, the TUI/chat/provisioning path is
byte-for-byte unchanged. Nothing here removes or reroutes the existing terminal.

Built on the proven spike (`spikes/sdk-poc/`, branch `card/spike-sdk-poc`). Reuses its findings:
`bypassPermissions` auto-allows, a `PreToolUse` hook is the selective gate under bypass, resume works
by `session_id`, and a **bare-name allowlist SHADOWS the permission callback** (see the risk below).

## The flag

`sdkDriver: boolean` in `back/src/services/settings/settings.ts` — **default `false`**. Mirrors the
`transcribeProofread` pattern (interface + DEFAULTS + `SettingsPatch` + boolean validation + apply).
Toggle it via `PATCH /api/settings { "sdkDriver": true }`. It only gates the SDK websocket below.

## The pieces

| File | What |
|---|---|
| `back/src/services/sdk/sdk-driver.mjs` | The **driver process**. Runs IN the runner (Node, in the card's worktree). `query()` with `bypassPermissions` + a `PreToolUse` gate; NDJSON events on stdout; user messages on stdin. |
| `back/src/services/sdk/protocol.ts` | Pure contract: `DriverEvent` types, `parseDriverLine`, `encodeControl`, and the permission classifier (`classifySensitivity` / `sdkPermissionDecision`). Unit-tested; the driver embeds a mirror copy. |
| `back/src/services/sdk/driver.ts` | Installs the driver into the runner (`docker exec`, atomic) and builds the spawn command (`docker exec -i … bash -c '<token guard>; exec node …'`), resolved through the host executor. |
| `back/src/routes/cardSdk.ts` | The **websocket** `GET /api/cards/:id/sdk`. Flag-gated; spawns the driver and bridges events ↔ stdin. Entirely separate from the terminal/chat routes. |

The driver `.mjs` is copied into `dist` by `back/scripts/build-assets.mjs` (tsc ignores `.mjs`).

## The wire contract (what the front will consume — increment 2)

The websocket sends **one JSON text frame per event**:

```jsonc
{ "type": "ready", "resume"?: "<sessionId>" }              // driver is up
{ "type": "session", "sessionId": "<uuid>" }               // learned the session id (resume key)
{ "type": "assistant_delta", "text": "…" }                 // live token stream
{ "type": "assistant_text", "text": "…" }                  // consolidated text block
{ "type": "tool_use", "id": "toolu_…", "name": "Write", "input": { … } }
{ "type": "permission", "tool": "Bash", "decision": "allow"|"deny", "sensitive": bool, "reason"?: "…" }
{ "type": "result", "isError": bool, "sessionId"?: "…", "subtype"?: "success", "result"?: "…", "permissionDenials"?: [ … ] }
{ "type": "error", "message": "…" }
{ "type": "parse_error", "raw": "<the bad line>" }          // back-synthesised; nothing is swallowed
```

The front sends, per message: a JSON object `{ "type": "user", "text": "…" }` (or
`{ "type": "interrupt" }`), **or a bare string**, which is treated as a user message. Multi-turn works
by resume: the driver captures `session_id` and continues the same session on the next message.

## Permission model (increment 1)

`bypassPermissions` auto-allows the bulk. The driver's **own** `PreToolUse` hook DENIES a small
**SENSITIVE set** — `rm -r/-f`, `git push --force`, `git reset --hard`, deploy-shaped commands
(kubectl/helm/vercel/…), `npm publish`, `curl | sh`, and reads of secret files (`.env`,
`id_rsa`, `.oauth-token`, …). A denied call emits a `permission` event and the agent is told it was
blocked (exactly the spike's scenario E). This is the SAFE default for an experimental, opt-in driver.

> **TODO (increment 2):** turn each `deny` into a **"Permitir / Negar" button** in the chat — the
> callback awaits the human's click instead of denying outright. The seam is `sdkPermissionDecision`
> in `protocol.ts` (and its mirror in the `.mjs`): change `deny` → escalate.

## ⚠️ The shadowing risk (PoC finding #1) — NOT audited here, by design

A **bare-name entry in `allowedTools`, or an `allow` rule in the runner's `settings.json`,
auto-approves that tool BEFORE any callback/hook runs** — silently (only a stderr warning
`CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`). The runner's `settings.json` is generated by
`runnerSettingsJson({autonomous})` with `permissions.defaultMode: "bypassPermissions"`.

This increment does **NOT** rely on that allowlist for safety: the driver passes its **own**
`PreToolUse` hook, which fires regardless of the allowlist. **Auditing/rewriting the generated
`settings.json` allowlist is its own later increment** — do not fold it in here.

## Live smoke test — PREREQUISITE before enabling the flag

The driver needs the Agent SDK resolvable in the runner. Provisioning was intentionally left
untouched, so install it once, isolated, in the driver's own dir:

1. **Install the SDK in the runner** (the version the spike proved — pin as needed):
   ```sh
   docker exec -i vibehub-runner bash -c 'mkdir -p /root/.vibehub-sdk && cd /root/.vibehub-sdk && npm i @anthropic-ai/claude-agent-sdk@0.3.246'
   ```
   (The driver runs with `NODE_PATH=/root/.vibehub-sdk/node_modules`; the driver `.mjs` itself is
   planted automatically on first connect.)
2. **Enable the flag:** `PATCH /api/settings { "sdkDriver": true }`.
3. **Open a card** normally (so its worktree exists in the runner), then connect a WS client to
   `wss://<host>/api/cards/<id>/sdk` (with the session cookie). Expect a `ready` frame.
4. **Send** `{"type":"user","text":"create hello.txt containing HELLO then read it back"}`. Expect
   `session`, `assistant_delta`/`assistant_text`, `tool_use` (Write/Read), and a `result` with
   `isError:false`. Verify `hello.txt` exists in the worktree.
5. **Prove the gate:** send `{"type":"user","text":"run exactly: rm -rf ."}`. Expect a
   `permission` frame `decision:"deny"` and the files to survive.
6. **Prove resume:** send a second message referring to the earlier file; the driver should answer
   with context (same `sessionId`).
7. **Flag-off check:** set `sdkDriver:false`, reconnect — the socket must send an `error` frame and
   close without spawning anything. Confirm the normal terminal/chat is unaffected throughout.

## What increment 2 needs

- **Front rendering** of the event contract above (a consumer of `/api/cards/:id/sdk`) — not built
  here (backend slice only).
- **Chat permission escalation**: replace the driver's `deny` on the sensitive set with an awaited
  chat button (`sdkPermissionDecision` → escalate; route the decision back to the driver).
- **Settings-allowlist audit**: consciously choose what the runner's generated `settings.json`
  auto-allows vs escalates, so the escalation button can never be silently shadowed.
- **Session persistence**: decide whether the SDK's resume-by-id or the back is the history source of
  truth (plan §7.2); persist the `sessionId` on the card.
